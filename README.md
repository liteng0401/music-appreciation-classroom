# 高中音乐鉴赏 · 互动课堂教学网页

人音版《普通高中教科书·音乐·必修·音乐鉴赏》（2019 年版）的互动教学网页，供音乐教师在课堂上直接打开使用。

## 功能
- 按 **序篇 / 上篇（第一—八单元）/ 下篇（第九—十八单元）** 导航，每单元一页
- 每单元含：**本节要点 · 核心框架/概念 · 关键术语 · 鉴赏思路 · 作品鉴赏 · 拓展聆听 · 配套资源下载 · 聆听示范 · 学习要点**
- **随堂练习**：选择题 + 判断题，提交即显对错与解析，顶部进度条，按单元计分
- **术语速查**：全书 113 条术语，可搜索
- **对比速查**：民歌/乐种/京剧行当/西方史期/曲式/歌剧/爵士等速查表
- 浅色/深色主题切换，适配投影仪；纯前端、可离线打开
- **校本品牌与便签**：侧栏显示河北峰峰第一中学校徽；右下角 📝 全局悬浮便签，上课随手记校本补充，仅存本机浏览器
- **作品音频播放**：每首作品卡片带「▶ 播放」按钮（有音频才显示），点击即播；底部悬浮播放条显示曲名、可停止
- **🎧 拓展聆听（选听）**：教材「拓展与探究」里未列入正文曲目表的音频，按课本编号归入对应单元，同样可点播
- **📎 配套资源下载**：每单元列出配套的 PPT 课件与教案 Word，显示文件名与体积，点击即下载
- **🗂 补充资料区**：每单元底部一块「教师投稿」区，收录老师们自己上传的 **音频 / 视频 / PPT / 文本** 资料；音频走页面统一的浮动播放条，文本可页面内展开阅读；配「＋ 提交补充材料」入口（指向腾讯问卷投稿表单）

## 使用
- **公网在线打开**：https://liteng0401.github.io/music-appreciation-classroom/ （GitHub Pages，仓库已公开）
- 也可直接双击本地 `index.html` 打开（纯前端、可离线，无需联网、无需服务器；但音频与 PPT 下载需在线或本地文件齐全）。

### 两套 PPT 的区别（重要）
| | 位置 | 份数/体积 | 说明 |
|---|---|---|---|
| **网盘原版课件** | Release 附件区 `ppt-v1` | 52 份 / 2.0 GB | 网上搜集的人音版配套课件原件，**未经压缩**。网页「📎 配套资源下载」里点按钮即从此处下载 |
| **本项目自制课件** | 仓库 `ppt/` 目录 | 35 份 / 3.1 MB | 由 `generate_ppt.py` 生成，含变易教学设计的四图式、随堂练习，体积小、便于二次编辑 |

> Release 附件名被 GitHub 强制改成纯 ASCII（中文会被吞掉），故统一编号为 `<单元>-<序号>.pptx`（如 `ch04-02.pptx`），与网页条目顺序一一对应；网页上仍显示中文文件名。

### 课件 PPT 的三条下载路径（重要 · 2026-09-22 实测）

学校网络（国内、无科学上网）实测结论，直接决定页面上按钮怎么排：

| 路径 | 页面上的位置 | 国内无代理可用？ | 要登录？ |
|---|---|---|---|
| **GitHub 加速镜像** | 每个 PPT 条目右侧的「下载 ↗」 | ✅ 可以（约 330 KB/s） | 否 |
| **微云打包 zip** | 每个 PPT 区块下方的「📦 本单元课件打包下载」 | ✅ 可以 | ⚠️ **需扫码登录微云**（微信/QQ 均可，一次即可） |
| GitHub Release 原始直链 | 不出现在页面上（镜像就是它的前缀） | ❌ 超时 | 否（但打不开） |
| 站内 `media/jiaoan/` | 教案 Word 条目 | ✅ 可以（GitHub Pages 国内可直连） | 否 |

- **踩过的坑（已修）**：PPT 条目的下载链接原先用的是数据里的 `path`（`media/ppt/...`），但该目录被 gitignore 了、线上并不存在，**线上点任何一个 PPT 都是 404**。现改为优先用 `url`（Release 附件）；`path` 只作为本地双击打开网页时的兜底。教案 Word 不受影响，仍用 `path`。
- **微云的登录限制是实测的**：用真实浏览器 + 直连（出口 IP 国内运营商，确认未走代理）在全新匿名上下文里点「普通下载」/「极速下载」，均立刻弹出微信/QQ 登录框，一个字节都没下到。所以微云方案解决的是「不用科学上网」，不是「不用登录」。
- 其它候选为什么没选：**Gitee 发行版**总附件上限 1GB（我们 2.02GB 装不下）；**123 云盘**免登录下载仅限单文件 <100MB；**腾讯云 COS / 阿里云 OSS** 体验最好但要实名 + 可能产生流量费；**WorkBuddy 云服务存储**文档明确不提供公开链接（只给已登录用户签名链接）。

#### 加速镜像是怎么接的（只有一处配置）

`index.html` 里两个常量，改 `DL_MIRROR` 就能换镜像或关掉：

```js
const DL_MIRROR = "https://ghproxy.net/";   // 改成 "" 即退回 GitHub 直链（需科学上网）
const mirror = u => (DL_MIRROR && /^https:\/\/github\.com\//i.test(u||"")) ? DL_MIRROR + u : (u||"");
```

`mirror()` 只改写 `github.com` 开头的地址，所以**教案（相对路径 `media/jiaoan/`）自动不受影响**。

镜像选型实测（2026-09-22，本机 `--noproxy '*'` 真直连）：

| 镜像 | 结果 |
|---|---|
| `ghproxy.net` | ✅ **采用**，均速 ~326 KB/s，52 个附件全部 206 |
| `gh-proxy.com` | ✅ 可用但慢（~140 KB/s） |
| `ghfast.top` / `gh.llkk.cc` / `mirror.ghproxy.com` / `ghproxy.cc` / `hub.gitmirror.com` / `github.moeyy.xyz` / `gh.xxooo.cf` / `ghps.cc` | ❌ 全部已失效 |

完整性验证：22.5MB 文件经镜像下全，**SHA-256 与源文件一字不差**，`unzip -t` 无报错；Range 请求返回 206（可断点续传）。

> ⚠️ 加速镜像是**第三方公共服务，不由我们控制**，可能随时限速/失效。所以**微云那条路要保留**，
> 两条路互为兜底。发现镜像挂了：换个域名改 `DL_MIRROR`，或临时置空回退直链。

#### 微云镜像怎么生成 / 怎么更新

```bash
python3 build_ppt_zips.py                 # 19 个单元各打一个 zip → .ppt_zip/（已 gitignore）
python3 tools/weiyun_put.py .ppt_zip/*.zip --pdir_key <微云目录key>   # 上传（可断点续传，秒传生效）
python3 tools/gen_ppt_mirror.py           # 建分享链接 → ppt_mirror.js（页面读它）
```

- 上传走宿主给连接器起的**本地 MCP 代理**（`tools/mcp_weiyun.py`），不需要给微云单独授权；脚本里的分块哈希直接复用微云官方 Skill 的实现，避免协议写错。
- 一轮预上传会返回 **4 个 512KB 通道**，必须一轮内并行传完再去要下一轮；只传一个通道的话速度只有 1/4（实测 186KB/s → 443KB/s）。
- 分享链接缓存在 `tools/pptshare_links.json`，**别删**：删了重跑会生成一批重复分享。

> ⚠️ **微云连接器有每日调用配额，配额用尽是硬停**：
> `code 117401 rate limit exceeded, daily quota used up. Please try again tomorrow`。
> 实测把 19 个包（约 2GB，每个分片一次调用）传完后，**`gen_share_link` 也会被同一配额挡住**
> ——也就是说「传完了但拿不到分享链接」是完全可能的，得上限重置后再补。
> `tools/gen_ppt_mirror.py` 已做容错：拿不到分享就跳过该单元、继续处理其余，
> **不会因为一个失败而整个文件写不出来**。批量任务务必留出第二天的补跑余量。


## 随堂练习：怎么生成 / 怎么自检

练习题**不是手写的**，由 `generate_data.py` 从 `~/.workbuddy/skills/music-appreciation/` 的章节 md 生成，`random.seed(20260921)` 固定，**同一份源文件必然生成同一份 `data.js`**（可用它校验改动）。三类题：

| 题型 | 数量 | 来源 |
|---|---|---|
| 概念选择题 `choice` | 每单元最多 6 | `frameworks` + `concepts` 的术语/释义，同类释义互为干扰项 |
| 作品选择题 `choice` | 每单元最多 3 | 作品表的「作者/来源」，同单元其他作者作干扰项 |
| 判断题 `judge` | 每单元 2 | `Anti-patterns`（常见误区）的 mistake/why |

改源文件后重跑，**必须看到这一行才算过**：

```bash
python3 generate_data.py
# 习题自检: 通过（无重复题干 / 无重复选项 / 答案与解析齐全）
# 判断题答案分布: {'正确': 19, '错误': 19}
```

自检会拦下：同单元/跨单元题干重复、同一题选项重复、`options` 少于 2 项、`answer` 越界、`explain` 为空。**自检不过就不要提交。**

> 🐞 2026-09-22 修掉的三处（都出在生成器，不在页面代码）：
> 1. `make_judge_quiz` 写成了 `for mistake, why in unit["anti"][:n]` —— `anti` 的元素是 **dict**，直接 `for a, b in` 会迭代出**键名**，于是 **19 单元 × 2 = 38 道判断题**的题干字面成了「判断：「mistake」是鉴赏时的正确做法。」、解析字面成了 `why`（老师报告"第二单元最后两道题一模一样"即此）。改为按键取值，并让两句判断题一句反问（答案"错误"）一句正述（答案"正确"），答案不再是清一色"错误"。
> 2. 术语池 `frameworks + concepts` 未按术语去重，同名术语可能被抽中两次 → 出两道一模一样的题（ch03「打溜子」、ch07「舞剧音乐」、ch08「欧洲音乐」已复现；ch05/ch12/ch14/ch15 属同类隐患）。
> 3. 作者干扰池未去重 → 同一题里出现两个相同选项（ch09《阳关三叠》两个「古曲」，实际只有 3 个有效项）。
>
> 修复代价：题数守恒（19 单元仍是 197 题、每单元题数不变），但重排了随机序列，**约 65 道题的题干换新、102 道题保留题干但选项顺序可能不同**。想避免以后再"改一处、全单元重排"，可把 `random.seed(20260921)` 改成**按单元播种**（如 `seed(20260921 + int(u["id"][2:]))`），代价是当场所有单元都会重排一次。

### 素材来源与匹配规则
- 素材源：网盘「人音版 素材」下的三套目录 —— 音频 mp3（100 个）、课件 PPT（52 个）、教案 word（33 个）。
- 音频匹配：按曲名归一化后算二元组相似度（阈值 70 分），`import_audio.py` 里的 `OVERRIDE` 表处理自动匹配不到的（如《费加罗的婚礼》序曲，源文件名仅为 `85.序曲.mp3`）。
- 拓展音频归属：MP3 文件名带教材流水号，按「最后一个已结束的单元」规则推断归属，归入 `audio_extra.js`。

## 补充资料区：老师怎么投稿

纯静态网页本身**没有服务器，收不了文件**，所以投稿走「外部表单收集 + 本地回填」：

```
老师填腾讯问卷              →  我拉取回答         →  回填并发布
（选单元+课次、选类型、传文件）    （MCP list_answers）   （ingest_supplement.py → supplementary.js → push）
```

### 1. 投稿表单（腾讯问卷）
表单字段与「必需满足的两条要求」一一对应：

| 题目 | 题型 | 对应要求 |
|---|---|---|
| 属于哪个单元、哪一课？ | **联动题**（选完单元自动过滤课次） | 要求 1：选择对应的单元和课程 |
| 材料类型 | 单选题：音频 / 视频 / PPT·课件 / 文本·文档 | 要求 2：选择材料的类型 |
| 资料名称 | 单行文本（必答） | — |
| 上传资料文件 | **附件题** | — |
| 文件太大？粘贴网盘链接 | 单行文本（选填） | — |
| 补充说明 | 多行文本（选填） | — |
| 投稿人 | 单行文本（选填） | — |

表单定义由 `build_survey.py` 按 `data.js` 的真实单元/作品结构生成（19 个单元 / 107 行课程），
避免手写错漏；生成后交给腾讯问卷 MCP 的 `create_survey` 创建，拿到投放链接。

```bash
python3 build_survey.py            # 生成 survey_text_linked.txt（联动题版）
                                   # 与 survey_text_twodropdown.txt（兜底：两个独立下拉题）
```

### 2. 拉回答并回填

```bash
# 用腾讯问卷 MCP 的 list_answers 把回答存成 answers.json，然后：
python3 ingest_supplement.py answers.json \
    --submit-url https://wj.qq.com/s2/<id>/<hash> \
    --dry-run                       # 先看解析结果，确认无误再去掉 --dry-run
```

可选参数：
- `--only-approved` — 只收录 `approved.txt` 里列出的标题（**人工审核**后再发布）
- `--links link_map.json` — 附件题只给了文件名时，用 `{标题: 分享链接}` 补上直链
- `--tip "…"` — 自定义页面上投稿区的说明文案

脚本会做类型归一、单元归属解析、链接合法性校验（只放行 `http(s)`）和转义，最后写出 `supplementary.js`。
网页端 `supportCard()` 渲染时**对所有外部内容再转义一次**，并用 `supUrl()` 二次校验链接协议——投稿内容来自外部，按不可信内容处理。

### 3. 页面上的呈现
- 音频 → 「▶ 播放」，走页面底部统一的浮动播放条（与教材音频体验一致）
- 视频 → 「▶ 播放 ↗」新窗口播放
- PPT → 「下载 ↗」
- 文本 → 「展开阅读」，正文直接在页面内展开
- 无投稿的单元显示空态提示；投稿入口未开放时按钮显示「投稿入口尚未开放」，不会出现死链
